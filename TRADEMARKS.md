# Trademarks and Project Identity

**Collaborative Keystone** is the canonical name of the original project created by River Madrid.

The software in this repository is licensed separately under the GNU AGPL v3.0.
That software license does not grant rights to use the project's name, logo, or official branding in a way that suggests endorsement, affiliation, or identity with the official project.

## You may

- truthfully refer to this project by name when describing its origin
- state that your project is a fork of Collaborative Keystone
- preserve legally required attribution and license notices
- run the AGPL software under the software license, provided your deployment is clearly distinguished from official/authorized Keystone instances

## You may not

- present your fork as the official Collaborative Keystone project
- use the Collaborative Keystone name or logo in a way that implies endorsement or authorization
- copy the project's branding or identity in a way likely to confuse users about source or ownership
- present a modified or unverified deployment as a signed official release
- use the `{Locale} Keystone` naming pattern in a way that conflicts with the global registry, official status labels, or user trust

## Product Identity Layers

- **Keystone Core** refers to the open-source software and public requirements.
- **Global Keystone** refers to the canonical official service and trusted locale registry.
- **Locale Keystone Distribution** refers to an official signed release package for launching a locale instance.
- **Community Fork** refers to a modified or independently operated deployment that is not verified as official.

Community forks must preserve required license and attribution notices while clearly distinguishing themselves from Global Keystone and authorized locale instances.

## Authorized Locale Branding

The `{Locale Display Name} Keystone` pattern is intended for approved locale deployments, such as `World Keystone`, `Castle Rock Keystone`, or `Douglas County Keystone`.

Official or authorized use of that pattern requires project approval, a current operator agreement, registry listing, and truthful source/provenance surfaces. The working agreement template lives in `docs/operator-agreement-template.md`.

Global Keystone and the signed locale registry decide whether a deployment may claim canonical, official, authorized, or verified status. A deployment marked stale, warning, suspended, compromised, abandoned, community, unverified, or development must not present itself as official.

## Source And Provenance Labels

Every running instance should visibly provide Source, AGPL, Build Info, and Registry links. Those links help users distinguish AGPL software rights from official brand rights.
